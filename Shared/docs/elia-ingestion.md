# Elia solar ingestion

This CLI prepares real Belgian national solar data for the existing upload
workflow. It does not change forecasting algorithms or claim benchmark accuracy.
Read the [benchmark protocol](belgian-benchmark.md) before interpreting results.

## Download (PowerShell)

From `Backend`, using the existing virtual environment:

```powershell
.\.venv\Scripts\python.exe -m app.elia download --start 2024-01-01 --end 2026-01-01 --output ../Shared/data/elia/study-2024-2025
.\.venv\Scripts\python.exe -m app.elia download --start 2026-10-25 --end 2026-10-28 --output ../Shared/data/elia/transition-2026-10
```

Dates are Brussels local dates; start is inclusive and end is exclusive. A new
output directory is required. The CLI never replaces an existing download run.
On Linux/macOS use `.venv/bin/python`. No new runtime dependencies are introduced;
timezone data is supplied by the existing pandas environment on Windows.

The importer selects Belgium and, for ods209, Total. It splits requests into
ranges of at most 28 elapsed days, and at local midnight on 26 October 2026.
Each range uses a JSON export, rather than offset pagination, to avoid pagination
ceilings. A separate records query supplies the expected count; a truncated or
concurrently changed export fails the run. Retries are bounded (four attempts,
45-second request timeout, exponential backoff) for transient network errors,
HTTP 429 and selected server errors. Other HTTP errors fail immediately.
There is no resume: preserve a failed run for inspection and retry in a new directory.

## Artifacts

| Artifact | Meaning |
|---|---|
| `raw/` | Source metadata, counts and original export responses |
| `manifest.json` | Request URLs, retrieval times, raw checksums, source mappings and range coverage |
| `normalized.csv` | UTC timestamp, generation MW, monitored capacity MW, source dataset |
| `platform.csv` | UTC timestamp and generation MW, suitable for upload |
| `benchmark-reference.csv` | Separate Elia 11:00/18:00 day-ahead reference columns; never model inputs |
| `quality.json` | Counts of gaps, duplicates, invalid values, missing references and readiness |
| `artifacts.json` | SHA-256 hashes of the generated artifacts |
| `ATTRIBUTION.txt` | Source and licence credit, with transformations disclosed |

All local runs in `Shared/data/elia/` are Git-ignored. No full production
data is bundled with the application. Unit tests synthesize small source-schema
fixtures; they do not require the network.

## Offline rebuild and validation

```powershell
.\.venv\Scripts\python.exe -m app.elia rebuild --input ../Shared/data/elia/study-2024-2025
.\.venv\Scripts\python.exe -m pytest tests/test_elia.py -q
```

Rebuild verifies every raw checksum, complete manifest, chunk coverage and counts,
then regenerates the processed artifacts without network access. It replaces
derived artifacts only, not raw files or manifest. With identical snapshots and
the same importer version, generated bytes/checksums must be identical.
New downloads may differ because Elia can revise historical data. Checksums
detect accidental changes, not tampering by someone who also edits the manifest.

Exit codes: 0 = complete series; 2 = downloaded/rebuilt but target quality defects;
1 = download, schema, snapshot-integrity or argument failure. A complete manifest
means download completion, not that the production series passed quality checks.

Missing production stays blank, legitimate zero stays zero, and negative values
remain negative. Duplicate records remain in the output and invalidate readiness.
Unexpected region/connection/range records are rejected and counted, not summed.
Missing capacity or reference forecasts are reported separately and do not prevent
using otherwise valid production as a history-only target.

`series_ready` assesses target continuity/validity only; it does not certify
real-time availability, benchmark fairness or predictive skill. `platform_upload_ready`
also checks the app's 100,000-row limit. The existing uploader separately enforces
its 10 MB byte limit. Larger studies can be partitioned deliberately; never merge
series with duplicate timestamps to bypass limits.

## Use in the app

Upload `platform.csv`; map `timestamp` and `generation_mw`, leave capacity unmapped,
and validate. Existing model comparisons may be explored, but their rolling
fixed-lead scores are not the protocol's complete next-day evaluation.
Both the maximum trajectory length and measurement-availability handling still
need later implementation. No weather data or model training occurs in ingestion.

## Known limits

No historical first-publication timestamps or revision vintages are recovered.
The migration audit checks schema and continuity, not equivalence of Elia's
upscaling methodology. Export count checking cannot detect a value revision that
preserves the row count during a download; raw snapshots record what was returned.
Preserve source credit and [Elia's licence](https://opendata.elia.be/pages/licence/)
when distributing derived figures or data.
